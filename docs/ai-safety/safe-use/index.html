Safe use with AI agents

A runbook: which commands are safe to let an agent run, and the mistakes agents make.

This is a runbook for letting an AI assistant manage processes through OxidePM. The rule of thumb: let the AI read freely, and require a person to confirm anything that stops, restarts, deletes or truncates.

Commands by risk

Safe, read-only: status, show, logs, env list, describe, ping, top, --version, and check (without --fix) where the check adapter is installed.

Caution:

CommandNotes
start <target>Starts a process, or every app of a config file. Check the config first. An app that is already up is refused.
stop, restart, reloadBrief downtime. A stopped app stays stopped.
saveRefuses to replace a non-empty file with an empty list unless --force.
startupGenerates an autostart script.
resurrectStarts everything the registry says should run. Verify the saved state first.
check --fixInstalls dependencies and creates .env from a template.
deployHigh: pulls code and restarts processes on a remote host.
updateReplaces the installed binaries and stops a running daemon.

Dangerous: kill (stops the daemon and every app), delete, flush (the log contents are lost), restore, policy set, and show --reveal (its output ends up in the conversation).

Treat all as a higher-risk variant of every command that accepts it.

Mistakes agents make

MistakeWhat happens
A wrong modeThe process is run with the wrong runtime.
Guessed field namesThe file is refused and the unknown key is named, so nothing starts. restart is the key for the restart mode, not restart_mode.
restart = "always" for a process that exits normallyIt is restarted over and over, with a growing delay, until more than max_restarts exits fall inside crash_window.
A very high max_restartsA crash loop can run for a long time.
Editing the config while the app runsThe running process keeps the spec it was started with. Stop it, then start the file again.
env set or env unsetBoth are refused. Use --env or the config file.
--watch or watch = trueRefused. File watching is not available.
pkill or kill -9 instead of oxidepm stopOxidePM's state no longer matches the real processes.
flush to clean upIt destroys the diagnostic history. Rotation is already automatic.
Restarting an errored app without reading its logsYou find the cause first, then restart.
all when one app was meantUnrelated services are stopped or deleted.
A loop of its own (while true, cron, a watcher)Let OxidePM restart apps.

Rules

  1. Review a config an AI wrote before it is started. Confirm mode, script or bin, cwd, env, ports and the restart policy.
  2. Confirm before a destructive command: kill, delete, flush, or anything with all.
  3. Read the logs before you restart. oxidepm logs <name> first.
  4. Keep secrets out of prompts and configs. status, show, describe and env list do not show environment values, but command arguments, URLs, logs and config files are not scrubbed.
  5. Put the agent on agent.sock and set OXIDEPM_ACTOR, so the limits apply whatever it does. Mark the apps it may restart ai_control, and the ones it must not touch protected.
  6. Run oxidepm describe <name> after any config change.

Commands that adapters provide

web, monit, notify, deploy and the other commands that adapters provide are caution or dangerous requests, and they go through the same policy and audit log as every other command. A session command such as monit, which takes over a terminal, is refused for an AI actor unless its adapter says it may be driven by one.

The web API

The ui-web adapter listens on 127.0.0.1 and needs an access key for every request, loopback included. By default it can only show apps and restart, stop and reload the ones that list it under adapters; it cannot create or delete apps or flush logs. Do not give an AI the access key, and do not raise the adapter's level to admin for one. The daemon sees every request as the actor adapter:ui-web, and the audit log names it.
