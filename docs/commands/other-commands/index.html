Other commands

Update, backup and restore, env, top, completions, and the commands that adapters provide: web, monit, init, check, deploy and diff.

update

oxidepm update [--version X] [--force] updates to a release. See Upgrade.

backup and restore

backup writes the saved process list, the state database and the adapter registry to a tarball. It does not include daemon.toml or your app config files. restore restores them, and the daemon must not be running. -y overwrites existing files without asking. A backup does not include the notifier's configuration, because it holds tokens. It holds the adapter registry but not the adapter programs: after a restore every adapter is disabled and has no rights until you enable it again.

env

oxidepm env list <name> lists the keys of an app's environment. env set and env unset are refused. See Environment and hooks.

adapter

oxidepm adapter import, list, info, search, enable, disable, update and remove. See Import and enable.

Commands that come from adapters

On Linux, run oxidepm adapter import <name> --enable to install from the signed online catalogue. The examples below use --bundled for offline installation. Review the grant and confirm any requested permissions. See Provided by adapters for adapter names.

init and check

Use oxidepm adapter import --bundled init --enable to add config generation and oxidepm adapter import --bundled check --enable to add project checks.

init detects Node.js, Cargo, Python and Go projects and preserves existing configs. check reports on dependencies, lockfiles, environment files and port availability. With --strict, warnings make it fail. --fix can install Node dependencies and create .env from a template, and --set-env KEY=VALUE edits .env. Both write options are limited to projects within the current directory.

git-start

Run oxidepm adapter import --bundled git-start --enable to add the git-start command. The adapter prepares a Git checkout in its own state directory and starts it. Use --offline to reuse a local checkout or --no-start to prepare it without launching. --install opts into Node dependency installation. Add --allow-scripts to allow dependency lifecycle scripts.

deploy and diff

Run oxidepm adapter import --bundled deploy --enable to add both commands.

deploy pulls from origin on the remote branch, or the branch selected by --branch. It runs the optional --post command and restarts processes using the remote oxidepm executable, which --remote-bin can override. A restart failure returns exit status 3. diff shows recent commits, working-tree status and a diff summary. Both use noninteractive SSH and require a known-hosts entry. Both support --dry-run.

File watching

On Linux, install the watch service from the release bundle.

Review its permissions. If approval is deferred, run oxidepm adapter enable watch --accept <fingerprint> with the fingerprint printed by the import. Add this table to each app you want to restart when its files change.

Paths are relative to the app's working directory. If paths is omitted, the adapter watches that directory. Your ignore patterns extend the defaults, which include .git, node_modules and target.

web

Run oxidepm adapter import --bundled ui-web --enable before using these commands.

The adapter serves a REST API and a WebSocket on 127.0.0.1:9615. API endpoints other than /api/health require the X-API-Key header, even on loopback. The first start makes a random key in the adapter's config.toml. A browser WebSocket can send it through the oxidepm-key.<key> subprotocol alongside oxidepm.v1. The adapter validates Host. For writes and WebSocket upgrades, Origin must be absent or match the configured origin.

With the default lifecycle grant, it shows every app and can restart or stop the ones that list ui-web under adapters. The daemon applies its policy to each request from adapter:ui-web and records it in the audit log. Use a TLS reverse proxy when exposing the service outside a trusted network.

EndpointMethodKeyDescription
/api/healthGETNo{"ok":true}.
/api/processesGETYesAll apps.
/api/processes/:selectorGETYesOne app.
/api/processes/:selector/stopPOSTYesStop.
/api/processes/:selector/restartPOSTYesRestart.
/api/processes/:selector/logsGETYesLogs.
/api/pingGETYesAsk the daemon whether it is alive.
/api/save, /api/resurrectPOSTYesSave or start the saved apps. Requires admin.
/wsWebSocketYesThe daemon's lifecycle events as they happen.

POST /api/processes (start an app) and DELETE require the admin level and return 403 under the default grant. Use the Prometheus exporter for /metrics.

monit and top

Run oxidepm adapter import --bundled ui-tui --enable to add oxidepm monit. The terminal dashboard shows app state, CPU and memory, details and logs. It asks for y or n before stopping or restarting an app. The session needs a terminal for input and output and takes no arguments.

The dashboard uses Ratatui 0.30. Building ui-tui from source requires Rust 1.88 or newer.

oxidepm top, a live resource monitor, is still in the core.
