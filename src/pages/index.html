OxidePM is a process manager written in Rust.

OxidePM is a process manager written in Rust, for Linux servers. It keeps your apps running: it starts them, restarts them when they crash, keeps their logs and can bring them back after a reboot. You drive it from the command line. It is open source, under the MIT or Apache-2.0 licence, and it has limits for letting AI agents work with it. Compared with PM2 and with systemd.

Three ideas

Three ideas behind OxidePM

01

A small core that does one job

The daemon supervises processes. It starts your apps, restarts them with a growing delay, and stops restarting an app that is stuck in a crash loop.

On Linux, the installer enables the bundled Node.js, Python, Go and Rust runtimes. Add optional adapters for project checks, config generation, starting from Git, SSH deployments, file watching, notifications, Prometheus metrics, the web API and the terminal dashboard. The built-in cmd runtime runs any executable.

02

Adapters for everything else

Each adapter is a separate program. It talks to the daemon through a documented JSON-RPC protocol on its standard input and output, so you can write one in any language.

If an adapter crashes or hangs, the daemon drops it and carries on. The daemon never stops or restarts an app because an adapter failed.

Read the adapter protocol

03

Safe to hand to an AI agent

The daemon decides who is asking from the connection a request arrives on, and a claim can only make a request stricter. An agent on the agent socket is held to limits: it can read everything, may only stop or restart apps you opened to it, and can never start, delete or flush.

Mark an app as protected and agents can't change it. Most commands that change something can be rehearsed with --dry-run, and what agents ask for is written to an audit log.

The core

What it does out of the box

Everything on this sheet is in the core and works with no adapter. Running a Node.js, Python, Go or Rust app needs the runtime adapter that a release carries.

OxidePM core: featuresSheet 01
01

Daemon

Apps keep running after you close the terminal. save writes the list, resurrect starts it again, and startup writes a systemd or launchd unit for boot.

02

Crash restarts

A crashed app waits, then restarts with a delay that doubles up to a cap. More than 15 restarts in 10 minutes end it as errored, until a person starts it.

03

depends_on

An app waits until the apps it names are running, and fails closed if they never are (60 seconds by default). stop all stops dependents first.

04

Process groups

Each app runs in its own process group, and stopping the app signals the whole group. A child that starts its own session or detaches itself is not in it.

05

Clean environment

Apps don’t inherit the daemon’s environment. They get PATH, HOME and a few basics, plus what you pass with --env or env_file.

06

Health checks

HTTP, TCP or a script of your own.

07

Limits

Restart an app when it passes a memory or uptime limit.

08

Cron restarts

Restart an app on a cron schedule (UTC).

09

Clusters

Run up to 256 instances of one app. Instance i gets port port + i.

10

Logs

Captured per app and rotated by size (10 MB and 5 files by default). Gzip compression of rotated files is optional.

11

Scripting

--json output, and --dry-run on most commands that change something.

12

Adapter checks

An adapter is checked against a SHA-256 before it is installed, shows what it asks for before it can be enabled, and on Linux runs under Landlock and seccomp.

Errors carry stable E_… codes on the daemon socket, in the audit log and in the adapter protocol.

Limits

What it doesn't do

You should know these before you install it.

Windows
Not supported.
macOS
macOS supports the built-in cmd runtime. The adapter launcher and sandbox are Linux-only in this release.
Reload
There is no zero-downtime reload. A reload is a restart.
File watching
The watch adapter restarts opted-in apps when their files change.
Sandbox
It limits the damage a buggy adapter can do. It does not fully contain a hostile one. That is why every adapter is hash-checked and shows what it asks for before you enable it. Details.
